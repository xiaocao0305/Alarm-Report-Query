# Alarm Report Query  使用说明

版本：V3.0.1（与程序窗口标题版本一致，构建记录见 BUILD_INFO.txt）
日期：2026-10-17

---

## 一、这个软件做什么

读取 Alarm7 的 Rpt 历史报告库，把报警记录通过「用户账号 + 防区号」
关联到用户数据库里的防区配置，取出**防区位置**，以表格方式展示并支持导出 Excel。

解决的问题：Alarm7 原软件查询用户历史报警时只显示事件描述，
不显示防区位置。本工具补齐这一信息。

**重要说明**：「防区位置」取自当前配置的防区表，不保证与报警发生时一致；
未匹配到位置时显示「未查到位置」。

## 二、运行环境要求

| 项目 | 要求 |
|------|------|
| 操作系统 | Windows 7 / 8 / 10 / 11（32 位或 64 位均可） |
| Python | **不需要安装**（已打包在 exe 内） |
| Access 驱动 | **不需要安装**（使用 Windows 自带驱动） |
| Office / Excel | **不需要安装**（导出的是标准 .xlsx 格式，WPS 也能打开） |

| 网络 | 不需要联网（本机运行） |

## 三、怎么使用

1. 把整个文件夹拷贝到目标电脑任意位置。
2. **双击 `Alarm Report Query.exe`**。
3. 直接弹出软件窗口。

### 界面说明

| 控件 | 说明 |
|------|------|
| 数据源 | 本机有多套 Alarm7 时在此选择；显示的是所选安装的完整路径 |
| 重新加载配置 | 修改 config.ini 后点此立即生效，无需重启程序 |
| 开始日期 / 结束日期 | 选择查询的日期范围，点右侧日历图标可直接选日期 |
| 快捷按钮 | 当日报告 / 本周报告 / 本月报告，一键设置日期并立即查询 |
| 用户账号 | 输入完整账号（如 000007777）只查该用户；默认精确匹配 |
| 模糊查询 | 勾选后按「包含」方式匹配账号，用于只记得部分账号时 |
| 开始查询 | 执行查询；查询中窗口可操作，下方有进度条 |
| 取消 | 查询过程中可取消，取消后不产生结果 |
| 导出 Excel | 把当前结果导出为 .xlsx 文件（查询成功才可用） |

### 关于查询结果

- 结果正常：显示记录并统计命中数；条件变化后旧结果自动失效，需重新查询。
- **读取失败 / 缺月份文件**：会明确提示哪部分没读到，此时**导出被禁用**，
  避免把不完整的结果当成全部。
- 没有记录 vs 读取失败是两种不同提示：前者是真的没有符合条件的记录，
  后者代表数据不完整、无法确认。
- 单次最多显示 3000 条；达到上限时界面和 Excel 都会注明「仅显示部分记录」。
- 每次查询都会重新读取防区位置配置，补填或修改位置后重新查询即可看到，
  无需重启程序。
- 修改 config.ini 后点「重新加载配置」即可生效，无需重启。

### 快捷按钮说明

- **当日报告**：只查今天的记录
- **本周报告**：查本周一至今天的记录
- **本月报告**：查本月 1 号至今天的记录
- 点击后日期范围自动填好并立即查询，无需手动调整

### 表格颜色含义

- **绿色行** = 已匹配到防区位置（来自当前配置）
- **橙色行** = 未查到位置（可能是该防区未配置位置，也可能该账号+防区号
  在当前防区表里没有对应条目）

### 关于日期查询

- 默认查询范围为**本月初到今天**，可通过两个日期控件自行调整，
  或直接用「当日 / 本周 / 本月」快捷按钮。
- 工具会根据日期范围自动找到对应的月份库文件，跨月查询无需手动换库。
- 日期范围内的事件自动按时间排序展示。
- 查询固定为报警类事件（报警、窃盗、劫盗、紧急、求助），
  关联防区表固定使用 CPZone。

## 四、关于 Excel 导出

点击「导出 Excel」，选择保存位置即可生成 .xlsx 文件。导出文件包含：

- **表头样式**：蓝底白字，可直接阅读
- **行颜色**：与界面一致 —— 绿色行已匹配位置、橙色行未配置
- **冻结首行**：往下滚动时表头不动
- **自动筛选**：表头带筛选按钮，可在 Excel 里直接按用户、事件类型筛选

打开软件：Microsoft Excel 2007 及以上、WPS 表格均可打开。

## 五、关于配置（一般不用改）

首次运行会在 exe 同目录生成 `config.ini`。

通常在**留空**状态下工具会自动探测，无需修改。只有在自动探测
失败时，才需要手工填写路径，例如：

```ini
[paths]
alarm_dir = E:\XB运维\Alarm7
master_pwd = 数据库密码
```

### 重点提示

- 如果一台电脑上装了**多套 Alarm7**，请在「数据源」下拉框里选择
  你要查的那一套。程序会**记住上次的选择**，下次启动自动使用。
- **多套数据且尚未选择过时，程序不允许直接查询**，必须先在数据源下拉框
  选定一套——避免把不同库的报警和位置混在一起。
- 界面上显示的「Master 库」「报告目录」两个完整路径，
  就是本次查询实际读取的位置，以它为准。
- 如果所选路径失效（如移动硬盘拔出），程序会提示重新选择，
  **不会自动换成其他库**。
- config.ini 内容写错（如漏掉节标题）时，「重新加载配置」会明确报错，
  不会误报加载成功；修正后重新加载即可恢复查询。

## 六、常见问题

**Q1：双击后没反应 / 一闪而过？**
说明启动出错。程序会在同目录生成 `error.log`，请把该文件内容截图反馈。

**Q2：提示「未找到 Access ODBC 驱动」？**
本版使用系统自带 32 位驱动，正常情况下不会出现。
若出现，可安装「Microsoft Access Database Engine 2016 **32 位版**」。

**Q3：查出来防区位置大量显示「未查到位置」？**
「未查到位置」表示该账号+防区号在当前防区配置表里没有对应条目，
可能是该防区未填写位置，也可能是账号在配置表中不存在。
界面与 Excel 的列名为「防区位置（当前配置）」——位置取自当前配置，
**不保证与报警发生时一致**（Excel 的「查询说明」页有此提示和配置读取时间）。

**Q4：查询日期范围较大时很慢？**
筛选在数据库层面完成（SQL），速度比旧版快很多。
数据量特别大时仍需等待，查询过程中窗口可以操作，也可以点「取消」。

**Q5：查询结果只显示一部分？**
单次最多展示 3000 条；达到上限时状态栏和 Excel 都会注明「仅显示部分记录」。
建议缩小日期范围。

**Q6：导出按钮是灰的？**
以下情况导出被禁用：尚未查询、查询失败、缺少月份文件、本次查询没有记录。
这是刻意设计——防止把不完整的结果当成全部导出。重新成功查询后即可导出。

**Q7：改了 config.ini 怎么生效？**
点界面上的「重新加载配置」按钮即可，无需重启程序。
密码含 % 等特殊字符也能正确读取。

**Q8：能同时多个人用吗？**
本工具为本机单人使用，直接读写本机数据库，不涉及网络服务。

**Q9：杀毒软件报毒怎么办？**
PyInstaller 打包的程序偶尔会被误报。本程序不含任何网络外发行为，
仅在本机读写数据库。如有疑虑可加入白名单。

## 七、技术说明（供运维参考）

- 程序架构：Python 3.8（32 位）+ wxPython（桌面界面）+ pyodbc（数据库）
  + openpyxl（Excel 导出）。
- **查询在后台线程执行**（wxPython 主线程保持响应），通过 SQL WHERE
  在数据库层完成日期 / 报警类别 / 账号筛选，避免全量读取后再过滤；
  支持中途取消（在文件与批次边界检查取消标志）。
- 防区号位数差异：Rpt 库中 ZoneID 为 2 位（如 `02`），
  用户库中为 3 位（如 `002`），工具已自动补齐至 3 位后再关联，
  否则会全部失配。字母防区号（如 `00A`）原样保留。
- 账号匹配：默认 `ActID = 输入值` 完整精确匹配（保留前导 0，不自动补位）；
  勾选「模糊查询」后为 `ActID LIKE %输入%`。
- 数据来源：
  - 报警记录：`Rpt\AlmEvtYYYYMM.mdb` 的 D 系列表
  - 防区位置：`Master.mdb` 的 `CPZone.AtPos` 字段
  - 关联键：`ActID`（用户账号）+ `ZoneID`（防区号）
- ODBC 驱动：`Microsoft Access Driver (*.mdb)`（系统自带 32 位）。
- Excel 导出：openpyxl，所有字段按**文本**写入（`data_type='s'`），
  防止 `=` 开头内容被识别为公式、保留账号与防区号前导 0；
  附「查询说明」页记录查询条件、数据来源与位置配置读取时间。
- 错误信息统一脱敏处理，数据库密码不会出现在弹窗、日志或导出文件中。
- 版本：代码 `APP_VER`、窗口标题、本文档版本号保持一致（当前 V3.0.0）。
- 本工具**只读**数据库，不会修改 Alarm7 的任何数据。
- 源程序：`alarm7_zone_gui.py`（Python 3.8+，依赖 wxPython、pyodbc、openpyxl）
